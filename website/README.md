# 法语词汇学习网站 / Édito Atelier

正式网站：**https://franmotest.netlify.app/**。React/Vite 多课本法语→中文自测网站，游客本机保存，登录后通过 Netlify Identity 与 Blobs 同步词库和学习记录。

## 使用入口与功能

主导航固定为 **首页、课本过关、每日检测、词库统计、设置**。首页展示检测入口、当前课本进度、已自评词汇与累计判定，以及大型“我的课本”入口。网站介绍与教程位于首页和设置，词库生成教程另提供可下载版本。

| 内置课本 | 版本 | 词条 | Part |
| --- | --- | ---: | ---: |
| Édito B1 | 2023 | 1110 | 24 |
| Inspire A1 | 来源文件未标注版本 | 937 | 32 |
| Édito A2 | 2022 · 第 2 版 | 850 | 24 |

Part 与主题带中文标题。Édito B2 是待导入选项，“我的法语笔记”是 6 词演示。教材来源及翻译、音标校核情况见 [DATA_NOTICE.md](../DATA_NOTICE.md)。

- **课本过关**：单个 Part 按完整主题分组，检测页底部目录可随时切换 Part。已过关部分可重测；每轮判定累计到逐词对错统计，重复同一判定不重复计数，改选替换本轮原判定。
- **卡片交互**：整行可翻词，法语在翻开前后位置固定；长词优先完整显示，音标空间不足时换行。可切换两种布局；组内打乱默认关闭，在设置中开启。
- **每日检测**：至少过关 4 个 Part 后，从最近部分取两组、前两个部分各取一组、其余已过关部分随机取一组；每组单一主题、10 词。主题词数不足时提示，不借用未过关内容，不推进主进度。
- **普通检测**：从首页进入，五组各十词。B1 使用原第一单元 P1＋P2 词库与抽题规则；其他教材仅在第一单元两部分分别够 25 词时启用。每日与普通检测各有历史和累计次数，保留最近 20 轮。
- **词库统计**：支持法中搜索、Part/主题筛选、来源及音标状态；点击 Part 查看逐词对错次数。旧 `#/records` 和 `#/dictionary` 入口仍有效。
- **设置与备份**：卡片布局、打乱顺序、浅色/深色/跟随系统、账号资料、完整备份及单书主进度迁移。

“已自评词汇”表示已有判定的不同词条数，“累计判定”表示累计自评次数；重测可以增加后者，不代表新增词条。

## 一键导入与 AI 整理词库

在“我的课本”页面底部选择“一键导入词库”，支持未加密 XLSX、UTF-8 CSV、词条数组 JSON，每文件最多 8 MB、10,000 词。标准模板共 14 列，其中 6 列必填；预览章节、词数、样例和错误后确认导入。相同词库打开已有课本，不覆盖学习记录。

文件在浏览器中解析。正式网站游客保存本机数据，登录账号后导入词库随学习记录同步；源文件本身无需上传。请保留原文件并定期导出完整备份。

[词库生成与导入教程](AI词库生成与导入教程.md) 提供课本 PDF 提取步骤、校核说明和完整 AI 提示词；[空白 CSV 模板](法语词库_空白模板.csv) 可直接作为格式样例。网站不直接解析 PDF，AI 整理后的词条仍需对照原书校核。

## 账号、头像与保存

邮箱注册需确认邮件。登录后右上角圆形头像提供“切换账号”“设置”“退出登录”。浏览器会话支持续期恢复；刷新凭证过期或被撤销后需重新登录，不保存密码。

在设置中选择“账号设置”可修改 1–40 字昵称，上传或移除头像。JPG/PNG/WebP 原图最大 5 MB，浏览器居中裁剪并缩小为 256×256，点击“保存资料”才上传。Identity 用户资料只保存昵称和头像路径；修改资料只刷新当前账号信息，不重置学习进度。

正式游客和账号缓存使用 `franmo-atelier:v2:guest` / `franmo-atelier:v2:user:<id>`，包含书架、每本书的轮次与累计对错、每日/普通练习和设置。退出恢复原游客空间，各账号缓存独立。清理浏览器数据会移除游客记录。

同源旧版缓存首次读取时迁移并保留原缓存。旧网址与新网址属于不同浏览器来源，游客需在旧站导出，再到新站导入。可确认恢复完整多课本备份，或迁移单书主进度；网站与 ChatGPT 插件只通过文件迁移，不自动互相同步。

## 安装到桌面与离线使用（PWA）

首页和设置提供“安装到桌面”入口。支持安装提示的浏览器会显示“安装应用”；其他情况可展开安装说明：

完整说明见 [INSTALL.md](INSTALL.md)；发布附件位于 [GitHub Releases](https://github.com/Alain-0721/french-vocabulary-test/releases)。PWA 通过浏览器安装，Release 的 ZIP 是静态网站部署包。

- **iPhone / iPad**：用 Safari 打开网站，点分享 → 添加到主屏幕 → 添加。
- **安卓**：用 Chrome 打开，点安装应用，或在浏览器菜单选择安装应用 / 添加到主屏幕。
- **电脑**：用 Chrome 或 Edge 打开，点击地址栏的安装图标。

首次请保持联网，等显示“离线词库已准备好”后再断网。应用能离线打开三本内置课本、本机导入词库、翻词自评、复习与统计；原有每日检测的过关条件仍然适用。登录、注册、头像上传与云同步需要网络。添加到主屏幕后如未看到原浏览器的游客记录，可先导出完整备份，再在应用中导入。

离线重启使用上次账号的本机缓存，标注“需联网验证”，不把本机显示资料当作已认证身份，也不调用账号接口。离线修改仍保存在原账号空间。联网并打开应用后，先恢复 Identity 会话、核对云端 ETag，再上传；另一设备改过记录时会提示冲突，保留本机修改。登录失效后需重新登录原账号，本机记录不会删除。可从头像菜单“返回游客记录”，各空间互不覆盖。

Service Worker 只缓存应用页面、版本化静态资源与图标，不缓存 `/api/`、`/.netlify/` 或独立设计预览。每次构建生成独立缓存版本，全部资源准备成功后才可启用。新版本显示提示，确认“更新并重新打开”后再切换，更新不清除本机词库和进度；若其他窗口也在检测，先保存并关闭它们。

`scripts/pwa-build.mjs` 生成 `dist/sw.js`；`public/manifest.webmanifest` 定义应用入口与图标。图标沿用现有书本标识，运行 `node scripts/generate-app-icons.mjs` 可重新生成。`netlify.toml` 为 Service Worker 和应用清单设置重新验证响应头。安装支持及各平台行为参考 [MDN PWA 安装说明](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Making_PWAs_installable)。

## 本地开发与检查

需要 Node.js 22+。从仓库根目录进入网站目录：

```bash
cd website
npm ci
npm run dev
```

正式入口为 `index.html` → `src/site.jsx`，本地打开 `http://127.0.0.1:5173/`。`textbooks-preview.html` 为独立设计预览：不读写正式学习缓存和云端数据，检测进度刷新后重置，记住词库仅保存至预览本机空间。

```bash
npm test
npm run test:import
npm run test:study
npm run test:navigation
npm run test:account
npm run test:production
npm run test:profile
npm run typecheck
npm run build
npm run test:pwa
```

检查覆盖词库字段和错误文件、重测与计数、复习隔离、备份往返、旧数据迁移、模拟账号会话、昵称与头像、云端身份和条件更新。测试使用隔离样例，不访问真实用户进度。真实邮箱登录、邮件回调及两台设备同步需使用实际账号验收。

`test:pwa` 需先构建，检查清单和图标、完整缓存、离线账号记录与重连冲突。本地 PWA 验收需运行构建产物（例如 `npx vite preview --host 127.0.0.1`）；开发服务器不注册 Service Worker。

## Netlify 部署与接口

仓库根目录 `netlify.toml` 配置构建目录 `website`、命令 `npm run build`、产物 `dist` 和函数目录 `netlify/functions`（相对构建目录）。SPA 路由回退至 `index.html`。部署需要站点启用 Netlify Identity，并配置正式网址及邮件回调地址。

| 接口 | 用途与存储 |
| --- | --- |
| `/api/multi-progress` | 新版多课本完整记录，`franmo-progress-v2`，按认证用户 ID 隔离 |
| `/api/progress` | 保留的旧版接口；新版仅在新存储为空时只读迁移 `edito-progress` 数据 |
| `/api/avatar` | 登录后上传处理后的头像，存入 `franmo-avatars` |
| `/api/avatar/:filename` | 按随机文件名公开读取头像，上传不允许任意覆盖其他文件 |

进度写入校验身份、请求来源、数据结构与 ETag。冲突时保留本机记录，用户先导出备份，再读取云端。正式部署使用站点存储，预览部署使用隔离存储。头像上传同样校验登录、来源、图片类型与实际大小；随机路径用于展示头像。

已关联站点的手动部署示例：

```bash
npm run build
# 先部署预览并验收
npx netlify deploy --no-build --dir dist --functions netlify/functions --skip-functions-cache
# 再发布正式站点
npx netlify deploy --prod --no-build --dir dist --functions netlify/functions --skip-functions-cache
```

使用 `--no-build` 时显式传入函数目录，避免只上传静态页面。依赖、构建产物、`.netlify/`、密钥与个人备份不提交到 GitHub。
